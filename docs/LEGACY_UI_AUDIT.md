## 结论摘要

当前 `FraudShield2026` 还不能称为旧版软件的高相似迁移版。

按“导航结构 + 页面布局 + 字段顺序 + 页面行为 + 真实业务能力”综合评估，当前相似度大约在 **35%~45%**，远低于目标的 **90%+**。

主要原因不是单点样式问题，而是三类差距同时存在：

1. **壳像了，但页面骨架还没像**
2. **页面名字像了，但行为大多还是占位或模拟**
3. **旧版关键能力没有真正迁到服务端**

## 旧版系统真实结构

### 1. 登录层

旧版存在独立登录窗口，不是主壳直接进入：

- 固定尺寸登录窗
- 账号 / 密码 / 动态令牌三输入
- 显示密码勾选
- 状态栏提示
- 二次验证（TOTP）
- 机器码校验
- 可上报安全事件

关键问题：

- `SKIP_LOGIN = True`，实际默认绕过登录
- 登录能力和安全策略写死在 `Project/main.py`

### 2. 主壳层

旧版是典型 PyDracula 风格侧栏壳：

- 左侧深色导航
- 顶部自定义标题栏
- 可隐藏左侧菜单
- 底部状态栏显示账户级别与版本
- 左下角附加“软件信息”抽屉

导航项顺序固定：

1. 主页
2. 实时监测
3. 实时告警
4. 实时分析
5. 重点监测
6. 历史日志
7. 参数调整
8. 账户设置
9. 退出登录

### 3. 旧版页面能力

#### 主页 / 软件信息

- 更偏信息展示和说明
- 含软件介绍、免责声明、底栏信息

#### 实时监测

- 实时数据流表格
- 可点开交易详情
- 停止 / 继续滚动
- 数据来自 Kafka

#### 实时告警

- 可对节点右键封禁 / 放行
- 可整链封禁 / 放行
- 可保存分析图

#### 实时分析

- 4 个实时图表
- 总交易笔数 / 总金额 / 平均金额 / 资金流向
- 通过实时消息追加驱动

- 支持正常追踪 / 深度追踪
- 展示本地操作账号和云端重点关注账号

#### 历史日志

- 本地日志表
- 按时间模糊查询
- 按登录 ID 查询
- 导出账号
- 删除日志

#### 参数调整

- 高级参数编辑
- 当前软件版本 / 云端版本
- 当前模型版本 / 云端版本
- 当前参数版本 / 云端版本
- 检测软件更新
- 模型架构更新
- 模型参数更新

#### 账户设置

- 当前用户资料
- 动态密码校验后修改

## 旧版代码问题

以下问题是旧版重构时必须处理的，不然只是把问题从 PySide 平移到新壳里。

### 一、架构问题

- `Project/main.py` 单文件过大，职责混杂
- UI、数据库、模型、图谱、Kafka、报表、更新逻辑全部耦合在主窗口类
- 业务流依赖全局变量，如 `widgets`、`username`、`admin`
- 生成代码文件被直接承载业务理解成本较高

### 二、配置问题

- 存在大量硬编码路径，例如 `E:/Economy/...`
- 存在硬编码数据库地址、账号、密码
- 存在硬编码 Kafka 地址
- 存在硬编码模型加密密钥派生逻辑

### 三、运行可靠性问题

- `SKIP_LOGIN = True`
- `confirm_delete`、`update_kafka_status` 等函数为空
- Qt 与 `tkinter` 混用
- Windows 大小写不敏感掩盖了一些路径命名问题，例如 `Graph detect.py` / `graph detect.py`
- 本地数据库、远程数据库、云端数据表之间边界不清

### 四、可迁移性问题

- 太多行为依赖本地文件系统结构
- 太多行为假设 Windows
- 太多逻辑依赖同步阻塞式弹窗
- `pre6.py` 存在重复导入、职责堆叠、报表和模型耦合

## 新版 FraudShield2026 当前状态

### 已完成

- 新仓结构建立完成
- `Vue 3 + Tauri + FastAPI` 技术栈落地
- 主导航顺序与旧版基本一致
- 已有桌面壳、基础路由、系统概览、检测接口、实时 SSE、报告接口
- 有初步“旧模型目录是否存在”的兼容探测

### 未完成或仅为占位

#### 桌面端

- 没有旧版登录页
- 没有二次验证页
- 没有机器码校验链路
- 没有真正的软件信息抽屉

- `DetectionService` 目前只按金额做伪预测

  - Kafka

  - `pre6.py`
  - 账户数据库
  - 用户管理
  - 更新机制

## UI 相似度差距

### 1. 视觉主题差距

旧版视觉特征：

- 深色左栏
- 深色标题栏
- 紫色高亮
- 深色内容容器
- 图表、表格、分析区为桌面控件风格

新版当前视觉：

- 整体偏浅色米白 + 蓝紫
- 图标是文本字符
- 品牌区、标题栏、工作区的比例和层级都和旧版不同

结论：

- **导航文字顺序相似**
- **整体配色与控件质感不相似**

### 2. 页面结构差距

最严重的不是颜色，而是页面内部结构不一致。

例如：

- 旧版“实时告警”是告警表 + 链路分析 + 操作按钮 + 第二张实时表
- 新版“实时告警”是静态示意图 + 简化表格

- 旧版“历史日志”是查询条件 + 日志表 + 导出 / 删除动作
- 新版“历史日志”是报告列表

- 旧版“账户设置”是资料修改 + 验证码 + 账户表 + 增删改
- 新版“账户设置”只有静态输入和静态表

### 3. 交互语义差距

旧版很多按钮不是装饰，而是有明确后端动作：

- 开始分析
- 上传图片 / 文字 / 文件
- 添加重点关注
- 解除重点关注
- 检查更新
- 模型更新
- 参数更新
- 保存参数
- 添加账户
- 修改上传
- 保存图表
- 保存分析图表

新版大部分按钮尚未承载这些语义。

## 90% 相似度目标的判断标准

后续实现不应只看截图像不像，应按以下 5 个维度评估：

1. **导航结构一致**
2. **页面布局一致**
3. **字段顺序和文案一致**
4. **关键交互一致**
5. **主要业务结果一致**

建议的验收标准：

- 导航顺序与命名：100%
- 登录页结构：90%+
- 主壳布局：90%+
- 重点页面布局：90%+
- 上传分析链路：功能闭环可跑通
- 实时监测 / 告警：先做高仿 UI，再逐步替换为真实数据

## 推荐实施顺序

为了尽快把相似度抬到 90% 以上，建议严格按下面顺序做。

### 第一阶段：先把 UI 骨架拉齐

目标：让用户第一眼就认出是旧版软件。

优先项：

1. 新增独立登录页，复刻旧版登录结构
2. 重做桌面壳配色、字号、间距、图标、标题栏
3. 重做 8 个主页面的布局骨架
4. 保持旧版字段顺序、按钮文案、区域标题

### 第二阶段：把旧版行为迁进来

目标：页面不只是像，还能按旧习惯操作。

优先项：

1. `/analysis` 接入旧上传分析链路
2. `/logs` 恢复按时间 / 登录 ID 查询、导出、删除
3. `/accounts` 接入当前用户信息、账户列表、增删改
4. `/focus` 接入本地关注与云端关注列表
5. `/params` 接入版本信息与参数保存

### 第三阶段：替换模拟数据

目标：去掉 mock。

优先项：

1. 接入旧模型能力
2. 接入 OCR
3. 接入 Kafka 或兼容流源
4. 接入真实报表与历史产物
5. 接入鉴权
